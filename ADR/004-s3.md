# ADR-004: S3 for File Storage

**Status**: Accepted

**Date**: 2026-08-06

---

## Context

Users need to upload and store:
- Profile pictures
- Task attachments (documents, images, PDFs)
- Organization logos
- Export files (CSV, PDF reports)

Requirements: scalable, durable, cost-effective.

---

## Decision

We will use **AWS S3** for all file storage.

---

## Consequences

### Positive

- **Unlimited scale**: No capacity planning needed
- **Durability**: 99.999999999% (11 9's)
- **Low cost**: $0.023/GB/month
- **CDN integration**: CloudFront for fast delivery
- **Versioning**: Built-in file versioning
- **Access control**: Fine-grained IAM policies
- **Lifecycle policies**: Auto-delete or archive old files

### Negative

- **Vendor lock-in**: AWS-specific
- **Eventual consistency**: Rare edge case delays
- **Latency**: Higher than local disk (but mitigated by CDN)

---

## Alternatives Considered

### Local Disk Storage

**Pros**: Simple, fast access  
**Cons**: No redundancy, backup complexity, doesn't scale

### Database BLOB Storage

**Pros**: Simplifies architecture  
**Cons**: Expensive, slow queries, database bloat

### Google Cloud Storage / Azure Blob

**Pros**: Similar features to S3  
**Cons**: Team already on AWS, unnecessary multi-cloud complexity

---

## Why S3?

Industry standard, proven reliability, integrates with existing AWS infrastructure (CloudFront, Lambda, IAM).
